# 口径卡模板与判定示例

口径卡 = 把招聘需求翻译成「机器能判、人能复核」的三段条件。每段必须写清**算**与**不算**，否则判定器会把标签当证据、把意向当经历。

## 模板

```
c1 <条件名>：<主体> + <证据形态> + <时长/级别>
   算：…
   不算：…
c2 <条件名>：…
c3 <条件名>：…
地点：<优先城市>（只排序，不淘汰；除非用户明确要 pass）
```

## 示例 A：留学 + 英语可作工作语言 + 名企职能岗

- **c1 留学**：海外院校本科及以上。算：QS 前 500、港澳台院校、中外合作办学只认外方学历。不算：短期交换、线上学位、企业大学、中学及以下。
- **c2 英语**：A 级（专八 / 雅思分数 / 托福分数 / CATTI / TESOL / 翻译硕士 / 「英语可作为工作语言」原文）；A10（海外学位连续 ≥24 个月 + 明确英语能力表述）。不算：BOSS 标签「海归 / QS500」、只有「英语流利」四个字而无学历或分数支撑。
- **c3 名企职能岗**：非教培知名企业（外企总部 / 咨询 / 四大 / 互联网大厂职能线 / 金融总部 / 央国企总部）的职能序列（总助 / 管培 / HRBP / 运营 / 项目 / 财务 / 法务），任职月份 ≥24。不算：教培集团的教学岗（不能与「英语教学」叠加）、外包/派遣（除非注明并降级）、销售序列、三段经历全「至今」且与全日制硕士时间重叠。

## 示例 B：英语教学 + 英语强 + 大厂（不适合叠加）

同一段新东方「英语教师」经历，只能算「英语教学」，**不能再算「大厂职能岗」**——否则会把「教英语」当成「进过大厂」，这是最常见的假阳性。

## 示例 C：行政助理方向（早期口径）

- 行政/总助经历 + 英语教学经历 + 英语硬证据 + 知名企业。
- 城市只作排序：长沙优先，其它城市保留。
- 若用户说「放宽大厂」，把「知名企业」定义为知名企业/教育巨头（新东方、网易有道、欧莱雅、华润、顺丰、普华永道等），但仍要求岗位为职能序列、时长 ≥2 年。

## 判定要点（踩过的坑）

1. **求职意向 ≠ 工作经历**：卡片上「期望：英语教师」不算当过英语老师；必须有工作经历条目 + 公司 + 起止。
2. **标签 ≠ 证据**：BOSS 标签（QS500、海归、雅思7.0、名企大厂）是系统标签，不能作为学历/英语/任职证明。
3. **公司名出现 ≠ 任职**：优势段提到「服务过腾讯」不等于在腾讯任职；要在「职位」段（公司 + 角色 + 起止）里出现。
4. **日期配对**：卡片日期是独立 token，成对读作起止；「至今」按当前月计；教育条目（本科/硕士/博士/大专/高中）跳过。
5. **同名 / 姓名掩码**：key 统一 `姓名|年龄`；姓名前常有活跃标签（热搜/新牛人/刚刚活跃），解析时先剔除。
6. **在职状态 ≠ 看机会**：「在职-暂不考虑」也点得动收藏，但不代表能挖；台账里要标注。
7. **付费动作**：搜索页的「打招呼 / 联系Ta」消耗搜索畅聊卡；推荐页的「打招呼」也可能消耗权益。用户说「搜索里的人要付费」时，只做推荐页 + 收藏。

## 审核闸门（每 5 人）

输入：`review_batch_N.json` 的证据字段（card_id / 掩码姓名 / 年龄 / 城市 / 期望 / c1 月数与 segments / c2 等级与 evidence / c3 月数与 segments；**不含完整卡片原文**）。
输出（**闸门实际接受的文件，二选一不要混**）：
```json
{"batch":1,"digest":"<review_batch_1.json 的 digest>","approved_card_ids":["..."],"rejected_card_ids":["..."]}
```
> 注意：`{c1,c2,c3,evidence,c3_months,verdict}` 是**审核人自己的判断记录**（写在评审表/口头即可），**不能**直接当 `review_ok_N.json` 提交——闸门只认上面这个 schema，且 approved+rejected 必须覆盖全部候选、digest 一致。
任一条不成立 → FAIL，写明缺口；证据不足 → 未决，不进收藏清单。
