# 软条件审核清单（agent 逐条看的那部分）

分工：`judge.py` / `judge-qa-strict.py` 这类脚本负责**硬条件**（方向词、证据条数、学历、年限、城市、排除项）——毫秒级、0 token、可复现。
Agent 负责**软条件**——每张规则判 PASS 的卡都要读一遍，然后给 `approve` / `reject` + 一句理由。

## 读什么（按顺序，平均 200–400 token/张）
1. **证据强度**：是不是只有关键词堆砌？有没有「用了什么、解决什么问题、量级/结果」。
   - 例：`精通自动化测试，搭建 Pytest+Requests 框架，回归时间从 3 天降到 4 小时` = 强证据。
   - 例：`熟悉 python/shell，会写自动化工具` = 弱证据，不算。
2. **经历连续性**：多段 < 6 个月的短经历、空窗、频繁跳槽 → 兼职/项目制/稳定性差，标风险。
3. **岗位与公司类型**：互联网/自研 > 传统 IT；外包驻场、人力派遣直接扣分。
4. **城市与通勤**：期望城市与现居是否一致；异地是否明确「可到岗」。
5. **薪资匹配**：期望薪超出岗位区间 30% 以上 → 高风险（谈不成）。
6. **红旗**：培训包装（XX 教育 + 包就业）、简历模板痕迹、纯手工测试无自动化。
7. **亮点**：性能/接口/自动化框架、CI/CD、质量体系落地经验、带过 3 人以上团队。

## 输出什么
- `approve` 或 `reject`，加一句 ≤ 60 字的理由，理由里必须指向**具体文字证据**（缺证据也要说缺什么）。
- 写进 `decisions.jsonl`：

```json
{"ts":"2026-11-08T11:40:12+08:00","index":6,"name":"丁某","rule":"PASS","ai":"approve","reason":"自动化框架+JMeter 性能+鸿蒙认证，5 年连续测试岗；短段经历已确认是项目制","action":"fav","fav_text":"已收藏"}
```

## 抽查（防规则误杀）
每轮从**规则判 NEAR/FAIL** 的卡里随机抽 2 张自己扫一遍：
- 如果发现「规则判错、其实该收藏」→ 记录 `false_negative`，下一轮调规则（加同义词/放宽句式）。
- 如果发现规则没问题 → 只记一行 `spot_check_ok`，不占额度。

## 什么时候不看
- 规则判 FAIL 且命中排除项（外包/培训/方向不对）→ 直接跳过，不消耗审阅。
- 卡片缺关键信息（学历/年限缺失）→ 记 `unknown`，不猜、不收藏。
